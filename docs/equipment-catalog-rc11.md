# RC11 器材管理与故障记录

本轮新增器材台账维护，并修复“历史故障被当作当前故障”的展示。原预约新增、三角色修改、取消、维修恢复、验证码、审批和模型预算继续保留。初始化的10台器材只是虚构样例，可以新增自己的实物台账。

## 新增和编辑器材

解锁后进入“资源与预约 → 器材管理”。选择“新增器材”，填写名称、类别、能力和匿名确认人，点击预览，核对并勾选确认后保存。每台实物单独登记，系统生成唯一编号。新增不会调用模型，保存后的可用器材可供新增预约与调度候选使用。

“编辑器材”可改名称、类别和能力。设备是否故障由故障登记和维修检查流程管理；修改名称或能力不会自动修好器材。有有效预约时不能改变类别，也不能删掉预约需要的能力。并发更新会要求重新载入，防止覆盖其他人的修改。

## 移除和恢复

“移除器材”是归档，保留所有历史与引用，不物理删除数据。仍有有效预约时禁止移除；先在预约管理修改或取消相关预约，再回来移除。系统不会代你取消预约或改变分配。

移除后不出现在在用台账、可预约器材或新调度候选中。“已移除器材”可恢复，恢复保留移除前状态：原来故障的器材恢复后仍是故障，需要维修检查后才能恢复可用。每项操作都有预览、显式确认、版本核对、幂等事务、审计与保存后读回。

## 当前故障与历史记录

“异常调度与审批”默认只显示当前待处理故障：记录未解决，且器材当前确实故障或维护中。恢复正常后的相机A不会继续出现在这里。

切换“历史记录”可查看完整记录。标签包含器材名称、记录状态、生效时间、记录编号及器材当前状态；同一器材多次故障不会显示成无法区分的重复选项。历史只读，不提供重新生成或审批。旧记录没有被删除或合并。

相同器材的同一未解决故障重复提交复用原记录；内容不同但已有未解决故障时明确拒绝，提示先处理已有记录。维修解决后发生的新故障可正常登记为新的事件。故障记录与器材当前状态不一致时不会启动模型，应由维护者核对实际情况，不自动改写历史。

## 安全与数据

所有界面操作通过 Main 应用服务及动态验证码访问检查。器材管理不直接修改预约；资源变动使相关待批准方案过期，仍需重新生成和人工批准。业务库、安全状态和API额度账本分别保留。本轮无新付费或真实模型授权，使用明确标注的离线替身测试。

故障调度仍有明确规模边界：快照最多50条器材记录（包括保留的归档）、单次最多20条受影响预约。超过边界转人工处理，不放大模型预算或搜索限制。50台边界的离线正确性验证不等于50台规模的性能或真实AI评测。

日常启动仍使用D盘完整解压包中的“启动CampusOps.cmd”；Windows x64、Edge、Python3.12便携依赖要求不变。新电脑未受控绑定时保持锁定；所有者维护工具单独私下保管。不能发送本机含私有.env及使用记录的运行目录。

本轮实际测试数量、代码SHA、打包哈希和桌面截图以同目录交付收据为准。旧RC6—RC10证据只代表原版本；本轮异机和新真实AI验收未执行时如实写NotRun。
