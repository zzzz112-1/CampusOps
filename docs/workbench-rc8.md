# 中文工作台与维修恢复（0.2.0rc8）

使用完整解压到 D 盘的日常包，双击 CampusOps/启动CampusOps.cmd。
正常入口继续强制动态验证码。已有同机同 Windows 用户的绑定保留；不重新扫码、不复制种子进分发包。
新电脑保持锁定，仍由所有者通过单独维护工具受控导入同一条验证器记录。

资源与预约页分为“器材概览、登记故障、维修恢复、预约查询”。
器材概览可按名称/能力与状态筛选，预约可按器材和匿名借用者检索。
登记故障后点击“继续处理本次故障”，确认影响并明确点击生成，再核对方案、批准或拒绝。
历史演示数据仍为 2026 年 11 月 10—11 日，使用演示时间需主动选择；不更改系统时钟、认证时间或模型预算。

维修结束后：切换“维修恢复”→选择故障或维护中的器材→填写匿名确认人和维修检查说明
→勾选已完成维修与功能检查→点击“确认恢复可用”。只在实际检查完成后操作。
系统在一个事务内核对设备版本、恢复状态、关闭该器材未解决的故障、记录审计，并作废现有待审批方案。
设备版本过时会拒绝提交，请刷新核对。重复提交同一请求不会重复恢复或覆盖后续新故障。
恢复不改任何预约；已批准的替代预约不会自动搬回原器材。旧故障保留历史，不能再启动其工作流。
已批准的审计和结果保留；其他仍开放故障的过期方案须在新状态下重新生成和审批。

业务状态、模式、类别、能力、匿名借用者和已知程序生成摘要显示中文。
原始英文说明、错误码、模型名称、技术标识和证据编号保留在明确标记的折叠原始记录中，便于复核，未改写数据库历史。
无法可靠转换的自由文本不伪装成翻译；明确提示查看原文。不为翻译调用模型或消耗额度。

“锁定 / 退出”只结束当前会话。其他窗口、重新打开或会话过期后仍需有效验证码。
真实模型仅在原明确启用、有效配置和预算下由生成按钮触发；故障登记、维修、筛选、刷新、批准均不调用模型。
离线替身测试、故障注入与真实模型模式分别标记，模式标签不等于模型已经成功。

本轮只更新软件与相关使用说明，不重制比赛 PDF、PPT 或视频；真实云端与实际另一台电脑均须单独验收。
