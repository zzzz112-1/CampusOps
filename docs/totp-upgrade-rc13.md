# 保留原手机 CampusOps 记录：RC13 升级一页说明

适用于已有 RC7—RC12 绑定的所有者。**程序修复与测试不等于你的实际绑定已迁移。**
本轮不读取、迁移或重建你的真实安全库，不自动替换当前正在使用的 RC12 目录。

1. 保留旧运行包和使用数据。将新的日常包完整解压到 D 盘**新目录**，得到 `CampusOps`；
   将私有维护包解压为与之同级的 `CampusOps-Owner`。维护包只由你本人保管，不发给普通接收者。
2. 先关闭全部会访问安全状态的 CampusOps 新旧软件及维护窗口，使用原来运行软件的同一 Windows 用户。
   所有版本仍使用独立固定安全目录 `D:\CampusOps\var\security`；不要删除、复制覆盖或手动清零其中的文件。
3. 由你主动双击 `CampusOps-Owner\00-升级原绑定无需重新扫码.cmd`。窗口明确确认维护操作后，
   输入手机**原有 CampusOps 记录当前六位码**。仅在本机输入，不发给 Codex，不截码/二维码。
   如果本轮码刚用于旧软件解锁，等待下一轮；若正在冷却，等待冷却结束。
   本机开发目录也提供私有快捷入口 `D:\CampusOps\maintenance\升级现有绑定.cmd`，
   同样由你主动运行并在窗口中确认；不要在仍有旧实例运行时点击。
4. 工具先验证原绑定、原有限速及重放限制，生成 CurrentUser DPAPI 整体加密的一致性备份，
   再在事务中升级。**保留同一 TOTP 种子，既不生成新种子，也不要求重新扫码。**
   迁移保留既有失败计数/冷却，记录本次已消费时间步，并更新配置标识使旧会话失效。
5. 成功后等待下一轮验证码，从新目录的 `CampusOps\启动CampusOps.cmd` 打开并解锁。
   确认器材与预约数据来源符合你的原有部署安排；本次安全格式迁移不会复制或清空预约数据库、审计或模型预算。
   新解压包不携带你的业务库或 API Key，不能把“新包默认样例”误当成原有使用数据库。
6. 如果失败，保留原安全库和 `owner-backup-*.dpapi`，停止操作并联系维护者。
   不能通过删除绑定、清零计数、扩大验证码窗口或退回明文解决。正常程序遇到旧格式只会保持锁定。

安全目录权限另行确认：私有包的 `只读检查安全目录权限.cmd` 不解密绑定。
`确认后收紧安全目录权限.cmd` 会先显示范围、要求你关闭相关程序并输入确认文字，保存原 ACL 后，
仅保留当前 Windows 用户、SYSTEM、Administrators 的必要权限。**本轮未替你执行真实权限调整。**
恢复 ACL 使用私有 `owner_acl.py --restore <本机acl-before记录完整路径>`，再次明确确认；
恢复访问规则，Windows 可能规范化继承标记。不要公开含本机 SID 的维护记录。

注意：不要让旧程序与新程序同时写同一个安全库。旧包仅作受控人工回退参考，不能自动恢复旧备份；
备份可能包含较旧的消费状态，恢复必须按私有受控恢复流程重新核对。旧格式计数从前没有完整性保护，
迁移只能保护当前值及后续转换，不能证明旧历史从未被改写。

日常使用仍是六位/30秒、前后各一步、5次错误冷却60秒；会话最长2小时、闲置30分钟到期。
一个已用验证码要等下一轮才能解锁新会话。换 Windows 用户/电脑通常不能解密原 DPAPI 密文，
需要你在目标最终用户下私下配置同一手机记录；直接复制密文不是跨机配置。

手机遗失时没有日常自助恢复、万能码或远程撤销。优先使用你自行保管的验证器受控备份；
没有旧码时停止正常换绑，由所有者单独确认私有恢复维护，绝不在日常包增加后门。
该入口锁不保证抵御源码修改、同用户恶意进程或完整有效旧快照回滚。
