## 依赖与层次

- 已测试平台：Windows x64、Python 3.12.14、SQLite 3.53.1；暂不承诺 Python 3.11 兼容。
- 顶层依赖固定于 `pyproject.toml`，全部传递依赖固定于 `requirements.lock.txt`。
- UI 调用 `ApplicationPort`；`bootstrap.create_application()` 是 Main 提供的组合入口。
- Main `ApplicationService` 管理事故、运行、配置和方案持久化；通过 `OrchestrationPort` 注入
  Agent Core。低层 `create_application` 保持默认未注入，正式入口 `streamlit_app.py` 使用
  `create_configured_application` 组合已合入的 Core / UI。
- 编排器只获得 `ReadonlyPort` 和显式传入的 `ModelClientPort`。只读端口返回冻结快照/模型，
  唯一写方法 `append_run_step` 只追加当前运行日志，不能写预约、方案或审批。
- `domain.validation` 为纯函数。`storage` 仅由 Main 服务/CLI 使用。正常运行的预约更新
  SQL 仅在 `ApprovalService`。迁移与虚构种子/显式重置是离线初始化例外。

## 数据与状态

schema v1 包含设计中的 10 张业务表：equipment、reservations、incidents、agent_registry、
workflow_runs、run_steps、proposals、proposal_items、approvals、audit_log；另有
schema_migrations 和 project_metadata。迁移带校验和，遇到陌生库或未知迁移拒绝修改。
外键始终开启；查询连接以 `mode=ro` + `PRAGMA query_only=ON` 打开。

对设计表追加的执行信息包括 execution_mode、snapshot_fingerprint、result_json、error_json、
validation_json 和 run_steps 调用/重试计数。所有时间从有时区输入转换为 UTC，存为同一
微秒精度 ISO 格式。展示时由 UI 用 Asia/Shanghai 转换，不把本地时间混入数据库。

完整资源快照由排序后的全部设备、预约、事故形成 canonical JSON + SHA-256；
设备/预约版本、状态、要求、时间与开放事故均参与计算。任何资源快照变化均保守地使旧方案
过期，包含与该方案无关的资源变化；日志/Agent 配置不会使资源指纹变化。规划工具共享同一
事务捕获的不可变快照；Main 在保存方案和审批时重新读取。Agent Core 自行记录其选择时
的注册表、角色与工具版本，配置改变必须影响后续实际路由。

初始种子只有 10 件设备、20 条预约、6 个匿名别名、3 个 Agent 配置。其余业务表初始为空，
只有真实执行的 DEMO_SEEDED 审计，不制造模型调用、事故、方案或审批结果。
生成器可重复产生相同 JSON；重置前验证标记并备份，保留所有备份。

## 约束与事务

故障视为从 effective_at 到未来持续生效，P0 不实现维修恢复和自动改期。
受影响集合为原设备所有 ACTIVE 且 `ends_at > effective_at` 的预约，包括跨过故障生效
时刻的预约。登记事故将设备置为 FAULTED，不变更预约本身。

候选查询检查标签、状态、开放事故及已有预约；**单条候选可行不代表组合可行**。
最终方案必须恰好覆盖受影响预约，不允许遗漏、重复、夹带其他预约、改变原时间或继续使用
故障原设备。对替代后的全局 ACTIVE 预约检查 `[start,end)` 重叠，包括方案内部冲突。
组合搜索、软约束排序与有限回溯由已合入的 Agent Core solver 实现，Main 保持最终硬约束校验权。

审批在 `BEGIN IMMEDIATE` 写锁下完成：

1. 检查幂等键和已决策结果；只有 VALIDATED 的待审批方案可执行。
2. 在同一事务读取当前快照、版本、设备状态、全部预约，再次执行同一纯约束校验。
3. 过期则不改预约，持久标记方案/运行 STALE 并记录原因。
4. 通过则使用带版本条件的 UPDATE 更新全部目标预约；在同一事务读回验证结果。
5. 原子写入审批、审计、APPLIED 状态后 COMMIT；异常使预约、审批和成功审计整体回滚。

拒绝只更新决策与运行记录，预约不变。数据库 UNIQUE(proposal_id)、UNIQUE(idempotency_key)
与串行写锁一起约束重复请求。相同方案重复批准返回原已提交结果；冲突键返回结构化错误。
此阶段是授权本机管理员演示，尚未实现身份认证/RBAC，不宣称多用户生产安全。

## 组合入口与真实性

正式入口已注入 Core；未明确设置 CAMPUSOPS_LLM_ENABLED=true 时不读取提供商配置，
不建立模型客户端，有影响的运行返回 FAILED / PROVIDER_UNAVAILABLE 且调用数为 0。
明确启用后仍需手动配置单一 HTTPS 端点、模型与密钥，适配器建立不发请求，仅事故处理触发调用。

Core 已实现白名单路由、LangGraph 条件/并行/有限循环、结构化三角色与持久预算，
UI 三页面已通过同步 AppTest。Main 的离线跨层测试使用明确标记的 offline_mock_test；
另已单独实际完成一次三角色真实模型审批闭环和零模型Edge/WebSocket检查。
RC3三预约真实路径已完成tasks=3候选分派与全局校验/批准；无解和审批变化STALE也实测通过。
没有生产 mock fallback；显式故障注入反馈、浏览器触发模型和比赛交付仍需独立证据。
SQLite 无恶意本机代码隔离能力，边界依靠端口、文件所有权和测试。

预算账本是 Core 私有追加文件，位于工作树 var/model-budget/，调用前锁定并 fsync 预留；
请求超时/未知结果不退款，不自动修复损坏日志，演示业务库重置不会清空它。默认每运行 6 次，
每日 30 次；两次完整验证反馈可能需 7 次，预算先到即停。账本只协调当前工作树，不代替
服务商账户级免费额度和账单硬停止。UI现通过Main的可选ModelBudgetPort读取权威快照，
不可用时保持未知，不从可重置日志猜余额。预留与实际HTTP尝试仍分别显示。

开发安装固定已验证的源工作树根；wheel安装从明确的当前CampusOps项目上下文或Core私有
project_root参数确定根。缺少D盘/项目身份/文档标记时受控拒绝，不向父目录搜索、
不退到venv/Lib或C盘、不迁移旧账本。Main实装RC3 wheel后仍读取原路径且11条预留原字节不变。

组合工厂只读环境变量；显式operator入口仅在当前子进程从忽略的.env读取单一配置。
日志不记录模型Key。记录摘要/错误时不得记录认证 token、header、
原始提供商异常或个人信息；Main 对未处理编排器异常只持久化通用错误。
服务商额度/账单保护必须由实际使用者在真实调用前确认，不自动开通付费。

## D 盘与验证范围

工作树、各自 .venv、.cache/pip、.cache/uv、.cache/python、.tmp、var/data、var/logs 全在 D 盘。
dev-env.ps1 仅设置当前进程环境；pytest 为每次执行生成 D 盘唯一临时目录。

不承诺 Windows/Codex 系统级缓存完全不会写 C 盘，也不修改其他项目或全局设置。
