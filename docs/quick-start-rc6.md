# CampusOps / GearShift RC6 一页快速开始

只处理虚构社团器材故障后的同时间替代。运行前提：**Windows x64、D盘完整目录、Microsoft Edge、.NET Framework 4**。
便携包自带Python3.12和锁定依赖，无需另装Python；不支持的系统尚未验收。

| 步骤 | 操作与预期 |
| --- | --- |
| 1 打开 | 将ZIP完整解压到D盘新目录；不要覆盖旧工程。进入CampusOps，双击启动CampusOps.cmd或CampusOps.exe，再在小启动器点击“启动应用”。 |
| 2 检查 | 有问题先运行诊断环境.cmd。它输出中文检查和本目录var/logs中的新报告，不读密钥、不连接模型、不打开业务库、不重置预算。 |
| 3 选演示日期 | 固定预约日期为2026-11-10至11-11。选择演示相机A，主动展开“演示时段”，填入2026-11-11 08:00北京时间。当前日期更晚时可能正确得到NO_IMPACT。 |
| 4 登记 | 填写虚构故障原因、确认并登记，再点击“继续处理本次故障”。登记、换页、刷新、填写演示时间均不自动生成方案。 |
| 5 生成 | 点击“生成调整方案”。查看运行模式、实际调用数量、工具观察与规则来源，再看器材调整对照。预约此时保持不变。 |
| 6 审批与读回 | 填写匿名操作人，明确批准或拒绝。Main事务再次校验资源、预约和规则版本；过期方案不改预约。正常关窗后重开，刷新读取持久结果。 |

**三种模式分清楚：** 默认离线不启用模型，有影响但缺少模型时明确不可用，不伪造方案；真实AI需要本机手动配置.env、明确启用并确认服务商额度保护；历史回放只读旧记录，不能当成本版本重新执行。
TEST_INJECTED、offline_mock_test、failure_injection_test均不等同真实AI验收。

真实AI配置请参考同目录.env.example，密钥只留本地；不自动切付费服务。默认6次/运行、30次/UTC日，额外工具后续请求同样计入。余量不是新授权，超时也不退款或自动整场重试。

**配置目录与重启：** 桌面桥读取当前运行包目录里的 `.env`。工程根目录已有 `.env`，不代表另一个解压包也有配置；发布ZIP故意不含密钥。本机Main便利入口 `D:\CampusOps\启动CampusOps.cmd` 显式复用Main的既有预算账本。请从该入口重开，不要继续使用修改配置之前已打开的启动器或应用窗口。此绑定仅作用于该入口的子进程，不改系统环境。新增或修改配置后须正常关闭旧窗口再打开。

**保留的失败结果：** 启用AI不会自动重跑旧任务。若看到 `PROVIDER_UNAVAILABLE` 和0次调用，先核对运行时间：它可能是启用前的旧失败记录。正确重开后，只有用户明确点击“重新生成调整方案”才创建新的逻辑运行；不连续点击、不把旧记录视为这次模型成功或失败。后续请求仍可能被额度、网络、模型输出或验证拒绝，具体以新运行错误码为准。

本轮火山方舟 `doubao-seed-2-1-lite-260915` 的成功验收使用显式 `MODEL_THINKING=disabled`，输出上限仍为1600 Token；此前默认思考的一次输出不完整已安全停止并保留。使用该模型时建议手动采用这一已验配置，不自动更改其他服务商设置，也不提高上限。密钥只填本机私有配置，不能进入截图、源码或回传包。

在同一电脑移动包做真实验收时，需要复用已有预算权威目录，由维护者设置进程环境 `CAMPUSOPS_BUDGET_PROJECT_ROOT` 指向原有有效D盘CampusOps目录；它不能指向空账本，也不授权模型请求。当前本机收尾验收固定复用 `D:\CampusOps`。默认账本并不是服务商账户总消费记录，不能靠换目录获得新的费用授权。
演示时间按钮只改表单，不改系统时间、预约日期或预算账本。规则正文明确虚构，不能放松硬约束或扩大写权限。

不要单独移动EXE或runtime；不要在ZIP预览里直接运行。软件和诊断不会改变系统安全策略；如系统阻止运行，保留提示与报告交给Main。异机清单见teammate-checklist.md。
