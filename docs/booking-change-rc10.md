# RC10：修改预约，查看目标与失败原因

正常关闭旧版窗口，使用新的启动入口，输入手机原CampusOps动态验证码。
进入“资源与预约 → 预约管理 → 修改预约”，或从预约列表对选中记录点“修改所选预约”。

## 可以修改哪些内容

- 只更换同类器材：例如相机A故障，时间保持原样，改用可用且满足能力的相机B。
- 只改日期或时间：原相机仍可用且时段没有冲突时，可以继续使用原相机。
- 同时调整器材和时间：在表单中明确填写希望的时间与器材，系统只使用这些请求值。
- 调整匿名借用者别名及必要能力。不要填写真实学生姓名、学号、电话等个人资料。

原预约编号保留。生成只保存方案，人工批准时事务再次验证才更新，其他预约不移动。
不会由模型擅自改期、把相机换成其他类别设备，或为了产生方案分配故障设备。

## 如何选择器材

默认“自动匹配同类相机（推荐）”（其他类别显示对应名称）。程序排除故障、维护、
未解决事故、缺少能力及目标时段冲突的同类器材，三角色只能在合法候选里规划与验证。
原器材可用且符合修改时可以保留；原器材故障或仅请求换设备时，会查找其他合法同类器材。

下拉框也可选具体器材。选择“演示相机C · 故障”等目标，含义是仅接受这一台；不能安排时
会明确失败，不会偷偷改成B。可以在失败页点“改用自动匹配同类器材”，或自行选另一台。

日期、器材、能力与说明在同一修改表单中。可先改时间再选相机，不因选择器材而重跑并丢失未提交时间。
先点“预览修改请求”，核对器材、日期/时间、能力与匿名别名；勾选确认后点“生成修改方案”。
切换自动匹配和重新填写仅打开表单，不会自动重试模型，仍需明确预览和生成。
资源状态变化、出现新的故障提示及普通刷新会保持当前分区，不会把预约编辑突然切回器材概览。

## 没有方案也必须显示目标

失败、需人工处理和进行中都会显示原预约及“本次请求目标（未执行）”。
目标包括指定器材或自动同类范围、开始与结束时间、能力、匿名借用者与修改原因。
没有合法方案时after仍为空，页面不会把请求目标伪装为已验证或已保存的预约。

新运行保存Main基于运行开始快照的具体排除原因：

- 哪台器材为故障或维护中，是否仍有开放事故影响。
- 缺少哪些能力。
- 与哪条有效预约冲突，以及该预约的北京时间时段。
- 指定目标不属于原器材类别或没有对应设备。
- 指定一台不可用时，是否有其他符合当前请求的同类选项；不会因此自动改变指定目标。

若是模型未启用、输出异常、额度不足或超时，显示相应错误与原目标，不表示模型成功。
原有任务6请求、UTC日30请求、受限工具反馈和最多2次重规划的预算边界保持，不自动扩额或切换模型。

失败后“重新填写修改请求”保留原目标、日期、能力与说明；自动匹配按钮只改变器材选择方式，
保留其余目标。过期或资源变化仍需新预览与人工批准，不能强制执行旧方案。

## 历史记录与证据

RC9失败记录通常只有概括原因。RC10可以从原context.request还原其目标，显示当前读回器材状态，
并明确提示“未保存当时逐台器材的排除详情”。当前状态不冒充当时冻结诊断，不覆盖旧审计或补造历史。
新同类候选守卫纳入修改快照指纹，旧待批方案在批准时重新验证或变为过期。
